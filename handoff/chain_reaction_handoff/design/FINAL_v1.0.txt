MEGA MAN X: CHAIN REACTION
FINAL v1.0 DESIGN SPECIFICATION
Status: DESIGN FROZEN FOR IMPLEMENTATION
Target game: Mega Man X / Rockman X
Platform: Super Nintendo Entertainment System
Scope: Mega Man X1 only
Art policy: 100% existing Mega Man X1 graphical assets
Distribution: patch only, never ROM

===============================================================================
0. EXECUTIVE SUMMARY
===============================================================================

Mega Man X: CHAIN REACTION expands a real Mega Man X1 design concept:
defeating certain Mavericks can alter another Maverick's stage.

Retail Mega Man X already contains three major cross-stage reactions:

1. Chill Penguin defeated -> Flame Mammoth's factory freezes.
2. Storm Eagle defeated -> Death Rogumer damages Spark Mandrill's power plant,
   causing blackouts and disabling electricity-dependent hazards/attacks.
3. Launch Octopus defeated -> Sting Chameleon's forest/cavern floods.

CHAIN REACTION completes that idea across all eight Maverick stages without
changing what Mega Man X fundamentally is.

FINAL SYSTEM RULES:

- Every Maverick affects exactly ONE other Maverick stage.
- Every Maverick stage is affected by exactly ONE Maverick.
- Every stage has exactly TWO states: NORMAL and ALTERED.
- No stage has compound, stacked, or multi-trigger states.
- The original three Capcom stage reactions remain intact.
- Five new reactions extend the same design language.
- All boss fights, boss weaknesses, boss HP, weapons, and Sigma stages remain
  vanilla unless a technical hook requires a behaviorally invisible relocation.
- No new enemy species.
- No new pixel art.
- No X2/X3 graphics.
- All new presentation uses existing Mega Man X1 assets.
- Stage-order consequences are derived from existing Maverick defeat flags.
- No new story exposition or reaction UI is added.

PLAYER-FACING CONCEPT:

    "Every Maverick you defeat leaves exactly one believable mark elsewhere."

3. HISTORICAL / DESIGN BASIS
===============================================================================

Mega Man X1 already contains boss-triggered stage changes, and original Capcom
staff later described stage changes as part of the game's intended design:
stage order could cause the player to experience stages differently.

CHAIN REACTION therefore does NOT claim to restore a documented cut eight-stage
system.

The correct historical framing is:

    "CHAIN REACTION expands a documented Mega Man X1 design concept that Capcom
     implemented selectively in the retail game."

The five new reactions in this document are original CHAIN REACTION design
decisions. They are not presented as lost Capcom content.

===============================================================================

ALLOWED:

- imported graphics from unrelated games.

FAILSAFE RULE:

If a visual effect cannot be built cleanly from existing X1 assets, remove that
visual flourish and keep the gameplay state.

Gameplay correctness is more important than decorative ambition.

===============================================================================
5. VANILLA ENEMY-PHILOSOPHY RULE
===============================================================================

Retail X1's altered stages establish the enemy-design philosophy.

Capcom generally does NOT replace a stage's enemy roster when its environment
changes.

Instead, retail X1:
- changes terrain/hazards while leaving normal enemies in place;
- changes an existing enemy/miniboss behavior when the new environmental state
  directly affects it;
- allows existing enemies to exploit the altered environment.

Retail examples:

FLAME MAMMOTH AFTER CHILL PENGUIN
- terrain changes;
- factory enemy population remains fundamentally the same.

SPARK MANDRILL AFTER STORM EAGLE
- electrical hazards shut down;
- visibility changes;
- Thunder Slimer loses its electricity-dependent attack;
- normal enemy roster remains.

STING CHAMELEON AFTER LAUNCH OCTOPUS
- water appears;
- existing Amenhoppers gain water in which to move;
- normal enemy ecosystem remains.

CHAIN REACTION follows the same rule.

GLOBAL ENEMY RULES:
- no X2/X3 enemies;
- no invented enemy species;
- no roster swaps merely to make a stage "feel different";
- preserve vanilla placement wherever possible;
- behavior changes must be directly connected to the altered condition;
- no new boss AI;
- no new miniboss replacement;
- only ONE reaction intentionally increases enemy count:
  Boomer Kuwanger -> Armored Armadillo.

7. STAGE SPECIFICATION: CHILL PENGUIN
===============================================================================

SOURCE:
Flame Mammoth

STATE:
THAWING SNOW MOUNTAIN

TYPE:
New CHAIN REACTION state.

DESIGN LOGIC:
The Snow Mountain missile-base infrastructure and Flame Mammoth's industrial
complex are presented as sharing an old thermal-management/coolant network.

When Mammoth's weapons factory is destroyed, its emergency shutdown forces
stored industrial heat/hot coolant through the return side of the system,
causing localized thaw around the Snow Mountain installation.

This is localized industrial thaw.
It is NOT global climate change.

EXISTING-ASSET PRESENTATION:
- replace selected snow-covered foreground tiles with existing exposed
  rock/industrial tiles from X1;
- use existing bare structural/metal tiles already present in the stage;
- reuse existing X1 steam/smoke animation if VRAM permits;
- reuse existing X1 water animation only if it can be loaded cleanly without
  tile/palette pressure;
- otherwise omit literal water animation;
- use existing pipe/vent graphics;
- use the Heart Tank shelter's existing destroyed/open state rather than
  drawing a melted version;
- no custom dripping-icicle art;
- no custom meltwater sprites;
- no new palette artwork.

IMPORTANT PHYSICS RULE:
Do not add slippery-floor physics.
Do not add "less slippery" physics.
Snow Mountain in X1 does not need that mechanic for this reaction.

ENEMIES:
No additions.
No removals.
No relocation.
No AI changes.

Preserve all normal Snow Mountain encounters exactly.

ITEMS:
- Foot Parts route remains unchanged.
- Heart Tank remains in the exact vanilla location.
- If Flame Mammoth is defeated, the shelter that normally requires Fire Wave
  begins in its existing destroyed/open state.

This preserves the underlying progression relationship:
Mammoth must still be defeated first.

BOSS:
Chill Penguin remains 100% vanilla.

BALANCE:
Combat neutral.
Exploration modestly easier.
Major payoff is visual world-state continuity.

17. STATE IMPLEMENTATION ARCHITECTURE
===============================================================================

Each stage reads exactly ONE Maverick defeat flag.

Flame Mammoth     reads Chill Penguin flag
Chill Penguin     reads Flame Mammoth flag
Spark Mandrill    reads Storm Eagle flag
Boomer Kuwanger   reads Spark Mandrill flag
Armored Armadillo reads Boomer Kuwanger flag
Launch Octopus    reads Armored Armadillo flag
Sting Chameleon   reads Launch Octopus flag
Storm Eagle       reads Sting Chameleon flag

PSEUDO-LOGIC:

    altered = boss_defeated(stage_reaction_source[target_stage])

    if altered:
        load_altered_stage_state()
    else:
        load_retail_stage_state()

No combined-state table.
No secondary triggers.
No extra progression variable unless technically unavoidable.

The altered state must reconstruct correctly from the existing progression
flags after:
- death/checkpoint reload;
- stage exit and re-entry;
- valid password restoration.

===============================================================================
18. PASSWORD / PERSISTENCE DESIGN
===============================================================================

Do not separately save "reaction state."

The reaction is derived.

Example:

If the loaded password says Chill Penguin is defeated, Flame Mammoth must load
its frozen state.

If the loaded password says Flame Mammoth is defeated, Chill Penguin must load
its thawed state.

This principle applies to all eight stages.

If the original password system already preserves the relevant Maverick defeat
bits, no new password encoding should be introduced.

Any implementation that requires separate reaction persistence is considered
architecturally suspect and must be justified before acceptance.

27. IMPLEMENTATION TOOLING / APPROACH
===============================================================================

Recommended research/implementation foundation:
- X1-specific disassembly;
- current Mega Man X SNES recompilation as a source of documented runtime
  behavior and addresses;
- MegaED X for level/event/graphics inspection where useful;
- bsnes-plus, Mesen-S, or equivalent debugger for runtime tracing;
- scriptable ROM/hash validation;
- automated state tests where possible.

Implementation should prefer:
1. existing retail stage-state mechanism;
2. existing event/object state logic;
3. minimal targeted ASM hooks;
4. data-driven alternate layouts/events;
5. ROM expansion only when necessary.

Avoid building a completely separate reaction engine if the retail X1
condition/event architecture can be extended.

    "Oh. I killed THAT Maverick."

-> Mammoth's factory freezes.

Mammoth falls
-> Snow Mountain's industrial area thaws.

Eagle falls
-> his ship wrecks Mandrill's power plant.

Mandrill falls
-> city power returns and Kuwanger's tower fully wakes.

Kuwanger falls
-> Armadillo's strategic mine receives an extra Metal Wing patrol.

Armadillo falls
